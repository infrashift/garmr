A CUE-based policy evaluation engine for enforcing governance, security, and compliance policies across your infrastructure and CI/CD pipelines.

## Overview

Garmr provides a flexible, type-safe policy engine that uses [CUE](https://cuelang.org/) for policy definition. It supports:

- **20+ condition operators** for flexible rule construction
- **Target filtering** to apply policies to specific resource types
- **Namespace organization** for team-based policy management
- **Explicit, atomic reload** for zero-downtime policy updates: a set that fails to load never replaces the running one, and `garmr policy reload` confirms every instance converged on the same policy-set digest
- **Audit logging** with request correlation for compliance
- **CI/CD integration** via CLI and REST API

## Key Features

### Condition Operators

Each expression sets exactly one of `all`, `any`, `not`, `match`, `compare`, `forEach`, or `func`. A `match` checks the field at a path with one or more of these operators:

| Category | Operators |
|----------|-----------|
| Existence | `exists: true`, `exists: false` |
| Equality | `equals` |
| Comparison | `greaterThan`, `greaterThanOrEqual`, `lessThan`, `lessThanOrEqual` |
| String | `contains`, `hasPrefix`, `hasSuffix`, `pattern` (regex) |
| Set | `in`, `notIn` |
| Lists | `containsAll`, `containsAny`, `subsetOf`, `unique`, `uniqueBy`, `sorted` |
| Advanced | `length`, `semver`, `datetime` |

Combine checks with `all`, `any`, and `not`. Use `forEach` for list elements, `compare` for cross-field comparisons, and `func` for builtin calls. The schema types every expression, so a misspelled operator is rejected when the policy loads. Rules can apply conditionally (`when`), `forEach` can filter (`where`) and count matches, paths can project lists (`spec.containers[*].cpu`), and messages can name the failing element (`{{c.name}}`).

### Target Filtering

Apply policies only to specific resource types:

```cue
target: {
    resources: [
        "pod",
        "deployment",
        {
            kind: "configmap"
            namespaces: ["production"]
            labels: {env: "prod"}
        }
    ]
}
```

### Namespace Organization

Organize policies by team or function. A policy's namespace is its
`metadata.namespace` (default `"default"`); directories are a convention
for humans and carry no meaning to the loader:

```
policies/
├── security/       # policies declaring namespace: "security"
├── compliance/     # namespace: "compliance"
├── platform/       # namespace: "platform"
└── release/        # namespace: "release"
```

Callers select a namespace per evaluation (`garmr eval -n security`).

### Audit Logging

Every evaluation is logged as a JSON record, to a rotated file or to
stdout/stderr for the platform's log pipeline, with:
- Request ID and W3C trace ID for correlation
- Decision (allow/deny/warn), policies and rules evaluated, violations count
- The input's `kind` and `metadata.name`
- The caller: source IP, user agent, and the service-mesh identity (SPIFFE principal)

Validation, policy deletion and reload requests are audited too.

## Example Policy

```cue
package security

containerSecurity: {
    apiVersion: "policy.garmr.io/v1"
    kind: "Policy"
    metadata: {
        name: "container-security"
        namespace: "security"
    }
    spec: {
        description: "Enforce container security best practices"
        target: resources: ["pod", "deployment"]
        rules: [
            {
                id: "SEC-001"
                description: "Containers must not run as root"
                severity: "high"
                expr: {
                    forEach: {
                        path: "spec.containers"
                        as: "container"
                        condition: {
                            match: {
                                path: "container.securityContext.runAsNonRoot"
                                equals: true
                            }
                        }
                    }
                }
                message: "Container is running as root"
            }
        ]
        enforcement: action: "deny"
    }
}
```
